# Task Manager — Управление задачами проекта

Ты управляешь задачами проекта через файловую систему. Читай это как точную инструкцию: какую операцию выполнять, как формировать файлы, что говорить пользователю.

## Хранилище

Все файлы задач живут в `.claude/session/`:

```
.claude/session/
  tasks.md              # Индекс — реестр всех задач
  details/
    open-01-slug.md     # Открытая задача
    done-02-slug.md     # Закрытая задача
```

Перед любой операцией убедись что директория существует:

```bash
mkdir -p .claude/session/details/
```

## Маршрутизация операций

Определи операцию по ключевым словам в сообщении пользователя:

| Операция | Ключевые слова |
|----------|----------------|
| **create** | создай, добавь, новая задача, new task, запиши задачу |
| **list** | покажи задачи, список задач, что в очереди, какие задачи, что осталось, что открыто |
| **show** | покажи задачу #N, детали задачи, подробнее о задаче, расскажи о задаче |
| **update** | обнови задачу, измени задачу, приоритет задачи, поменяй |
| **close** | закрой задачу, выполнено, done, готово, закрываю, task done |
| **delete** | удали задачу, убери задачу, удалить |

Если операция неоднозначна — предпочти менее деструктивную (list > delete, show > close).

## Формат файла задачи

Каждая задача — markdown-файл с YAML frontmatter:

```markdown
---
id: 7
status: open
priority: HIGH
created: 2026-03-31
closed: null
blockedBy: []
tags: []
---

# Заголовок задачи

## Описание
Что нужно сделать.

## Контекст
Откуда пришла задача, связанные файлы, зависимости.

## План
- Конкретный шаг 1
- Конкретный шаг 2

## Как проверить
Команда, тест или критерий готовности.
```

Приоритеты: `HIGH`, `MEDIUM`, `LOW`. По умолчанию — `MEDIUM` если пользователь не указал.

## Именование файлов

- Открытая задача: `details/open-NN-slug.md`
- Закрытая задача: `details/done-NN-slug.md`

Где:
- `NN` — двузначный номер с ведущим нулём (01, 02, ..., 99, 100)
- `slug` — короткое латинское название из заголовка (max 30 символов, слова через дефис, только `a-z0-9-`)

Пример: `open-07-add-auth-middleware.md`

## Формат индекса tasks.md

```markdown
# Реестр задач проекта

Детали по каждой задаче → `details/`
Последнее обновление: YYYY-MM-DD

## Открытые

| # | Задача | Приоритет | Блокер |
|---|--------|-----------|--------|
| 3 | Добавить middleware авторизации | HIGH | — |
| 5 | Рефакторинг модуля users | MEDIUM | — |

## Выполненные

| # | Задача | Дата |
|---|--------|------|
| 1 | Настроить CI/CD | 2026-03-28 |
| 2 | Добавить линтер | 2026-03-29 |
```

## Последовательная нумерация

ID никогда не сбрасывается. Для определения следующего ID:

1. Прочитай `tasks.md` — найди наибольший ID в таблицах
2. Если `tasks.md` нет — просмотри файлы в `details/`, найди наибольший номер в именах файлов
3. Следующий ID = max_найденный + 1
4. Если задач нет совсем — начинай с 1

## Политика подтверждений

| Операция | Действие |
|----------|----------|
| create | Выполнить молча |
| list | Выполнить молча |
| show | Выполнить молча |
| update | Выполнить молча |

## Операции — подробные инструкции

### CREATE — Создать задачу

1. Убедись что `.claude/session/details/` существует
2. Определи следующий ID (последовательная нумерация)
3. Извлеки из сообщения пользователя:
   - Заголовок задачи (краткое название)
   - Описание (что нужно сделать)
   - Приоритет (если упомянут, иначе MEDIUM)
   - Теги (если упомянуты)
4. Сформируй slug из заголовка
5. Создай файл `details/open-NN-slug.md` с полным frontmatter и разделами
6. Обнови `tasks.md`: добавь строку в таблицу "Открытые", обнови дату
7. Если `tasks.md` не существует — создай его с нуля
8. Ответь пользователю: `Задача #N создана: {заголовок}`

**Пример ответа:**
```
Задача #7 создана: Добавить middleware авторизации
```

---

### LIST — Показать список задач

1. Прочитай `tasks.md`
2. Если файл не существует — ответь: `Задач нет`
3. Выведи таблицы "Открытые" и "Выполненные" из файла
4. Если таблица открытых пустая — добавь строку `Открытых задач нет`

---

### SHOW — Показать задачу

1. Определи ID задачи из сообщения пользователя (ищи `#N` или число)
2. Найди файл в `details/` с соответствующим номером (open-NN-* или done-NN-*)
3. Если файл не найден — ответь: `Задача #N не найдена`
4. Прочитай файл и выведи содержимое пользователю

---

### UPDATE — Обновить задачу

1. Определи ID задачи из сообщения
2. Найди файл задачи в `details/`
3. Если файл не найден — ответь: `Задача #N не найдена`
4. Определи что нужно изменить (приоритет, описание, план, теги, blockedBy)
5. Обнови файл — измени только указанные поля
6. Если изменился приоритет — обнови и строку в `tasks.md`
7. Обнови дату "Последнее обновление" в `tasks.md`
8. Ответь: `Задача #N обновлена`

---

### CLOSE — Закрыть задачу

1. Определи ID задачи из сообщения
2. Найди файл `details/open-NN-slug.md`
3. Если файл не найден — ответь: `Задача #N не найдена или уже закрыта`
4. **Спроси подтверждение:** используй AskUserQuestion с вопросом:
   `Закрыть задачу #N: {заголовок}?`
5. Если пользователь подтвердил:
   - Переименуй файл: `open-NN-slug.md` → `done-NN-slug.md`
   - Обнови frontmatter: `status: open` → `status: done`, `closed: YYYY-MM-DD` (сегодняшняя дата)
   - В `tasks.md`: удали строку из таблицы "Открытые", добавь строку в таблицу "Выполненные"
   - Обнови дату "Последнее обновление"
   - Ответь: `Задача #N закрыта: {заголовок}`
6. Если пользователь отказался — ответь: `Отменено`

---

### DELETE — Удалить задачу

1. Определи ID задачи из сообщения
2. Найди файл задачи в `details/` (open или done)
3. Если файл не найден — ответь: `Задача #N не найдена`
4. **Спроси подтверждение:** используй AskUserQuestion с вопросом:
   `Удалить задачу #N: {заголовок}? Это действие необратимо.`
5. Если пользователь подтвердил:
   - Удали файл из `details/`
   - Удали строку из соответствующей таблицы в `tasks.md`
   - Обнови дату "Последнее обновление"
   - Ответь: `Задача #N удалена`
6. Если пользователь отказался — ответь: `Отменено`

---

## Важные правила

- Текущую дату получай из системного контекста или переменной окружения. Формат: `YYYY-MM-DD`.
- Slug формируй только из символов `a-z`, `0-9` и `-`. Транслитерируй кириллицу при необходимости.
- Никогда не пропускай секции в файле задачи — если информации нет, оставь заглушку `(не указано)`.
- `tasks.md` — единственный индекс. Он всегда должен отражать реальное состояние `details/`.
- Если `tasks.md` рассинхронизирован с `details/` — при любой операции молча восстанови консистентность.
