# Задачи проекта — через cctm

Все операции выполняет CLI `cctm` (идёт с плагином, доступен в PATH). Файлы в `.claude/session/` руками не редактируй — только через cctm.

Если `cctm` не найден — скажи: «нужен cc-task-manager 2.x, обнови плагин» — и остановись.

Если проект был на формате 1.x, cctm мигрирует его сам при первом обращении и печатает отчёт
(в stderr, до результата команды). Отчёт покажи пользователю: сколько задач перенесено, где бэкап,
какие файлы не распознаны как задачи. **`cctm init` в таком проекте не запускай** — миграция уже
произошла или произойдёт автоматически.

## Маршрутизация

| Пользователь говорит | Команда |
|---|---|
| создай задачу, добавь таск | `cctm create --title "..." [--priority HIGH\|MEDIUM\|LOW] [--tags a,b]`, затем тело через `cctm set` |
| покажи задачи, что в очереди, что осталось | `cctm list` (активные) или `cctm list --status all` |
| что делать дальше, с чего начать | `cctm next` |
| покажи задачу #N, подробнее | `cctm show N` |
| обнови, поменяй приоритет, отложи | `cctm update N --priority P` / `--status deferred` / `--title "..."` / `--blocked-by M` |
| закрой, выполнено, done | `cctm close N` (+ тело закрытия, см. ниже) |
| отмени задачу | `cctm update N --status cancelled` |
| переоткрой | `cctm reopen N` |
| удали | `cctm delete N --force` — **только после подтверждения через AskUserQuestion** |
| найди задачу про X | `cctm grep "X"` |
| сверь с нативными задачами | `cctm sync` |

Всё, кроме delete, выполняй молча. Вывод cctm показывай пользователю как есть.

## Тело задачи

`create` создаёт только запись. Тело пиши отдельно: сохрани markdown во временный файл (Write) и передай:

```
cctm set N --md /tmp/.../body.md
```

Шаблон тела:

```markdown
## Описание
Что нужно сделать и почему.

## Контекст
Откуда пришла задача, связанные файлы.

## План
- Конкретный шаг
- Конкретный шаг

## Как проверить
Команда, тест или критерий готовности.
```

При закрытии — тело закрытия тем же способом:

```
cctm close N --md /tmp/.../done.md
```

```markdown
## Что сделано
- Конкретные действия

## Ключевые файлы
- path/to/file — что изменилось
```

Детали должны быть достаточны, чтобы агент в новой сессии продолжил без вопросов.
