Финализируй текущую сессию. Выполни шаги по порядку.

## Шаг 1: Локальные pre-шаги

Прочитай `.claude/finalize.local.md` в корне проекта (если существует).
Если есть секции `## before` или `## pre` — выполни их шаги ПРЕЖДЕ чем продолжать.

## Шаг 2: Инициализация хранилища

```bash
mkdir -p .claude/session/details/
```

## Шаг 3: Перенос из нативного стора Claude Code

Если существует `.claude/tasks/tasks.json` (нативный стор, его ведут тулы TaskCreate/TaskUpdate
во время сессии) — прочитай его. Реальный прогресс сессии часто оседает именно там.

Перенеси состояние в реестр:

- Задачи со статусом `done`/`completed` → в таблицу "Выполненные" + detail-файл `done-NN-slug.md`
- Открытые/заблокированные задачи, отсутствующие в реестре → в "Открытые" + detail-файл `open-NN-slug.md`
- В frontmatter detail-файлов заполняй `external_id` — ID задачи из `tasks.json` (например `T-019`)
- Контекст из поля `context` в `tasks.json` переноси в секции detail-файла (не теряй информацию)

Если `tasks.json` нет — пропусти шаг.

## Шаг 4: Обновление реестра задач

Прочитай текущие `.claude/session/tasks.md` и `.claude/session/queue.md` (если существуют).
Обнови на основе результатов сессии:

- Выполненные задачи → перенести в таблицу "Выполненные" (с датой сессии)
- Обнаруженные новые задачи → добавить в "Открытые" или "Отложенные"
- Закрытые detail-файлы: переименовать `open-` → `done-`
- Сквозная нумерация продолжается с последнего номера, никогда не сбрасывается
- Если `tasks.md` не существует — создать с нуля

Формат `tasks.md`:

```markdown
# Реестр задач проекта

Детали по каждой задаче → `details/`
Последнее обновление: YYYY-MM-DD

## Выполненные

| # | Задача | Дата |
|---|--------|------|
| 01 | Краткое описание | 2026-03-31 |

## Открытые

| # | Задача | Приоритет | Блокер |
|---|--------|-----------|--------|
| N | Краткое описание | HIGH/MEDIUM/LOW | Нет или #M |

## Отложенные

| # | Задача | Приоритет | Блокер |
|---|--------|-----------|--------|
```

## Шаг 5: Детали задач

Для каждой задачи из таблиц — файл в `.claude/session/details/`.

`external_id` — ID связанной задачи в нативном сторе `.claude/tasks/tasks.json`, иначе `null`.

**Выполненные задачи** (`done-NN-slug.md`):

```markdown
---
id: NN
external_id: null
status: done
priority: HIGH
created: YYYY-MM-DD
closed: YYYY-MM-DD
blockedBy: []
tags: []
---

# Название задачи

## Что сделано
- Конкретные действия (1-5 пунктов)

## Ключевые файлы
- path/to/file — что изменилось

## Как проверить
- Команда или способ проверки
```

**Открытые задачи** (`open-NN-slug.md`):

```markdown
---
id: NN
external_id: null
status: open
priority: HIGH
created: YYYY-MM-DD
closed: null
blockedBy: []
tags: []
---

# Название задачи

## Проблема
Что не так, почему нужно исправить.

## Контекст
Откуда взялась задача.

## План
Конкретный план: файлы, код, что изменить.

## Предусловие
Что нужно сделать до этого (или "Нет").

## Как проверить
Команда или тест после исправления.
```

## Шаг 6: Обновление queue.md

Обнови `.claude/session/queue.md` — расширенные описания задач в очереди с контекстом, порядком выполнения, артефактами.

## Шаг 7: Обновление CLAUDE.md

Если в ходе сессии изменились:
- Архитектура, пайплайн, ключевые компоненты
- Структура проекта (новые/удалённые директории)
- Правила работы

— обнови `CLAUDE.md` в корне проекта.

## Шаг 8: Локальные post-шаги

Если `.claude/finalize.local.md` существует — выполни оставшиеся шаги (те, что НЕ помечены как before/pre).

## Шаг 9: Отчёт пользователю

Всегда последний шаг. Покажи:

```
Сессия YYYY-MM-DD финализирована.
- Выполнено: X задач
- Открыто: Y задач (Z HIGH)
- Артефакт: .claude/session/tasks.md
```

Если были локальные шаги — добавь их результаты в отчёт.

---

## Правила

- НЕ пропускай задачи — даже мелкие фиксы и заметки
- Детали должны быть достаточны для агента в НОВОЙ сессии продолжить без дополнительных вопросов
- Открытые задачи с HIGH приоритетом → первые в следующей сессии
- Если в `.claude/session/` уже есть данные из предыдущих сессий — продолжай, не перезаписывай
