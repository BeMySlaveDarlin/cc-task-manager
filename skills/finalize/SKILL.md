Финализируй сессию. Выполни шаги по порядку.

Если `cctm` не найден — скажи: «нужен cc-task-manager 2.x, обнови плагин» — и остановись.

## Шаг 1 — Локальные pre-шаги

Прочитай `.claude/finalize.local.md` (если есть). Секции `## before` / `## pre` — выполни сейчас, остальные запомни для шага 7.

## Шаг 2 — Стор и синхронизация

`cctm sync` — переносит состояние нативных задач Claude Code в реестр.

Если проект был на формате 1.x, cctm мигрирует его сам и напечатает отчёт — включи его в итоговый
отчёт сессии. Если стора нет вообще (новый проект) — `cctm init`.

## Шаг 3 — Закрыть сделанное

Для каждой задачи, выполненной в этой сессии (включая уже закрытые синком, если тело пустое):

1. Напиши тело закрытия во временный файл:

```markdown
## Что сделано
- Конкретные действия (1–5 пунктов)

## Ключевые файлы
- path/to/file — что изменилось

## Как проверить
Команда или способ проверки.
```

2. `cctm close N --md <файл>` (для уже закрытых — `cctm set N --md <файл>`).

Не пропускай задачи — даже мелкие фиксы.

## Шаг 4 — Завести новое

Для каждой обнаруженной в сессии, но не сделанной работы:

1. `cctm create --title "..." --priority P [--tags ...] [--blocked-by N]`
2. Тело через `cctm set N --md <файл>` — разделы Описание / Контекст / План / Как проверить. Детали должны быть достаточны для агента в новой сессии.

## Шаг 5 — Handoff

Handoff — снимок этой сессии для следующей: чего нет в задачах, но без чего не продолжить.
У каждой сессии свой файл (`.claude/session/handoff/<key>.json`), параллельные сессии друг друга не перетирают.

1. Посмотри, кто ещё работал: `cctm handoff list --limit 5`. Если есть свежие чужие сессии —
   учти в тексте (что могло уехать вперёд) и упомяни в отчёте.
2. Напиши тело во временный файл:

```markdown
# Одна строка: чем занимались

## Что сделано
- Только суть, деталей достаточно в задачах

## Состояние
Где остановились, что наполовину, что сломано прямо сейчас.

## Следующий шаг
Одно конкретное действие. Эта секция подмешивается в контекст следующей сессии — пиши точно.

## Грабли
Тупики, решения и их причины, чего не повторять.
```

3. `cctm handoff write --md <файл>`

Списки задач cctm подставит сам (по привязке задач к сессии). Явно передавай `--closed`/`--created`/`--touched`
только если знаешь, что автоопределение промахнулось. Тело — сводка, не дневник: лимит 20000 символов.

## Шаг 6 — CLAUDE.md

Если в сессии изменились архитектура, структура проекта или правила работы — обнови `CLAUDE.md` проекта.

## Шаг 7 — Локальные post-шаги

Выполни оставшиеся шаги из `.claude/finalize.local.md`.

## Шаг 8 — Отчёт

```
Сессия {дата} финализирована.
- Выполнено: X задач
- Открыто: Y задач (Z HIGH)
- Handoff: записан ({key})
{вывод cctm list}
```

Результаты локальных шагов — тоже в отчёт.
