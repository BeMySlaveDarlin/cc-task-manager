# cc-task-manager

[English](README.en.md)

Claude Code plugin для управления задачами проекта. Состояние ведёт CLI `cctm` — модель только формулирует задачи, инварианты держит код.

## Требования

- Claude Code CLI
- python3
- macOS, Linux, Windows (WSL)

## Установка

### Как плагин Claude Code (рекомендуется)

```
/plugin marketplace add BeMySlaveDarlin/cc-task-manager
/plugin install cc-task-manager@bemyslavedarlin-cc-task-manager
```

### Ручная установка (legacy)

```bash
git clone https://github.com/BeMySlaveDarlin/cc-task-manager.git
cd cc-task-manager && bash install.sh
```

Legacy-режим не подключает hooks — автосинк работает только при установке плагином.

## Использование

Skills активируются по ключевым словам или явно:

- `/ts` — CRUD задач: «создай задачу», «покажи задачи», «закрой задачу #5»
- `/finalize` — финализация сессии: «финализируй», «подведи итоги»
- `/rs` — восстановление контекста: «продолжим», «где остановились»

CLI доступен и напрямую:

```
cctm list             # активные задачи
cctm next             # что делать дальше (без заблокированных)
cctm show 7           # задача целиком
cctm create --title "..." --priority HIGH
cctm close 7
cctm grep "auth"      # поиск по телам задач
cctm sync             # сверка с нативными задачами Claude Code
cctm doctor           # проверка инвариантов, в том числе форков стора в ворктри
cctm merge ../wt      # влить чужой стор (форк из ворктри) в этот
cctm export --md      # человекочитаемый дамп

cctm handoff latest   # снимок последней сессии этого ворктри и ветки
cctm handoff list     # кто и когда финализировался, по ворктри и веткам
cctm handoff show feat          # по key, ветке, ворктри, дате или слову из заголовка
cctm handoff show --task 12     # handoff, где есть задача 12
cctm handoff write --md handoff.md --attach probe.py --attach results/
```

## Хранение

`.claude/session/` целевого проекта:

```
meta.json               счётчик id, версия схемы
tasks/007.json          одна задача = один файл, вся целиком
handoff/2026-09-28_1249_feat_ab12cd34.json   снимок сессии: дата первой записи, ветка, key
handoff/2026-09-28_1249_feat_ab12cd34/       вложения этого handoff, если есть
```

Статусы: `open`, `deferred`, `done`, `cancelled`. Никаких markdown-файлов в сторе,
никакого дублирования состояния — индекс строится на лету.

### Синхронизация с нативным стором

Claude Code ведёт свои задачи (TaskCreate/TaskUpdate) в `~/.claude/tasks/session-*/`.
`cctm sync` находит сессии проекта, сопоставляет задачи (по связке `external`, затем по заголовку)
и переносит состояние в реестр. Hook `TaskCompleted` запускает синк автоматически, `SessionEnd` —
синк плюс handoff (`cctm session-end`), так что оборванная сессия не оставляет реестр протухшим.

### Хуки

| Событие | Команда | Что делает |
|---|---|---|
| `SessionStart` | `cctm session-start` | кладёт контекст прошлой сессии в новую |
| `TaskCompleted` | `cctm sync` | переносит статус задачи в реестр |
| `SessionEnd` | `cctm session-end` | синк + handoff оборванной сессии |

Хуки работают строго внутри своего проекта (как ищется стор — ниже). В каталоге без стора хук
молча выходит, а не подхватывает чужой реестр этажом выше.

## Ворктри, параллельные сессии, проекты без git

**Где стор.** Ближайший `.claude/session` от текущего каталога до корня git-репозитория.
Не нашёлся, а каталог — git worktree → стор основного чекаута: все ворктри ведут один реестр,
и `cctm init` из ворктри создаёт его там же, а не отдельный форк, который умрёт с
`git worktree remove`. Без git граница — каталог, где стартовала сессия (берётся из реестра
живых сессий Claude Code или из транскрипта): выше него поиск не идёт, поэтому проект без git
в `~/proj` не уезжает в `~/.claude/session`.

**Ветка.** Задача запоминает ветку, в которой её завели; в ворктри `cctm next` и `cctm list`
показывают задачи своей ветки первыми. Handoff запоминает ворктри и ветку: `SessionStart` берёт
handoff своего ворктри и ветки, чужие показывает строкой («ворктри repo-wt, ветка feat») и
не подсовывает как «прошлую сессию».

**Соседи.** Живая сессия в том же дереве (одна ветка, тот же каталог) попадает в контекст
новой: «в этом дереве работает сессия X — её правки в git status не твои». Задача, которую
последней трогала живая соседняя сессия, помечена в `next`/`list` значком ⚑. Это не захват:
ничего не хранится и не блокируется, закрылась сессия — метка пропала.

**Форки.** Если в ворктри уже есть свой стор (от старых версий), `cctm doctor` в основном
чекауте его покажет, а `cctm merge <ворктри> [--dry-run]` перенесёт задачи и handoff с новыми
номерами, пометит вероятные дубли тегом `dup` и переименует источник в `session-merged-*`.

## Контекст на старте сессии

Задачи и handoff бесполезны, пока агент их не прочитал. Скилл `/rs` срабатывает по фразе
пользователя («продолжим», «где остановились») — то есть может не сработать вовсе.
Хук `SessionStart` не спрашивает: он кладёт сводку в контекст новой сессии сам.

Отдаётся ~15 строк: шапка последнего handoff, его заголовок, счётчики задач, секция
«Следующий шаг» и три верхние задачи из `cctm next`. Полное тело handoff остаётся за `/rs` —
лить его на каждом старте значит жечь контекст.

Инжект идёт на `startup` и `clear`; на `resume` и `fork` пропускается — там транскрипт
и так восстановлен.

Режим на проект — ключ `session_start` в `meta.json`:

```
"session_start": "brief"   по умолчанию: сводка
"session_start": "full"    handoff целиком
"session_start": "off"     выключить
```

Посмотреть глазами то, что уедет в контекст:

```
cctm session-start --raw
```

## Handoff между сессиями

Задачи говорят «что», handoff — «где остановились». Пишется на `/finalize`, читается на `/rs`.

Файл на сессию, поэтому параллельные сессии не перетирают друг друга. Имя читается без открытия
файла: `2026-09-28_1249_feat_ab12cd34.json` — дата и время первой записи, ветка (без git её нет),
первые 8 символов session id. Перезапись того же handoff имя не меняет. Старые имена `<key>.json`
переименовываются при первой же записи handoff или `cctm doctor --fix`.

Нужный handoff ищется без чтения файлов: `cctm handoff show <запрос>` берёт свежий из совпавших
по key, ветке, имени ворктри, дате (`2026-09-27`) или слову из заголовка; `--task 12` — handoff,
где есть задача 12. `cctm handoff list [запрос]` группирует по ворктри и веткам, своя группа первой.

Вложения — для того, что нужно продолжению, но лежит вне git или в ворктри, который снесут:
`cctm handoff write --md h.md --attach probe.py --attach results/` копирует их в каталог рядом
с handoff (до 20 МБ на handoff). `show` перечисляет вложения с путём, prune удаляет их вместе с handoff.

Параллельные сессии не мешают друг другу: каждая пишет своё, `cctm handoff latest` отдаёт самый свежий handoff
своего ворктри и ветки и отдельной строкой сообщает, что параллельно писали ещё N сессий —
их видно в `cctm handoff list`.

Списки задач в handoff проставляются автоматически: каждая правка помечает задачу id сессии
(`session`, `touched_by`, `created_by` в JSON задачи), так что чужая работа в чужой handoff
не попадает, а задача, которую трогали две сессии, есть в handoff обеих.

Хук `SessionEnd` дописывает handoff сам:

- сессия закрылась без `/finalize`, но задачи трогала → технический handoff (`kind: auto`,
  списки задач без текста — видно, что вообще происходило);
- после `/finalize` ещё что-то делали → к сводке дописывается блок «После финализации»,
  ручной текст не затирается.

Хранится 20 последних, но по 3 свежих на каждый ворктри и ветку не вытесняются никогда — активный
ворктри не выдавит чужие. `cctm handoff prune --keep N --days D` — вручную.

## Миграция с 1.x

**Автоматическая.** Первое же обращение к реестру в проекте со старым форматом запускает миграцию:
делается бэкап `.claude/session.bak-YYYYMMDD`, задачи переносятся в JSON-стор, старые
`tasks.md` / `queue.md` / `details/` удаляются, печатается отчёт. Затем исходная команда выполняется как обычно.

Переносит `tasks.md` + `details/*.md` (включая `archive/`, датные имена, `cancelled-`/`superseded-`).
Файлы, не являющиеся задачами, остаются на месте и перечисляются в отчёте.

Ручной контроль, если нужен:

```
cctm --no-auto-migrate list        # отказаться от автомиграции, только сообщить (exit 3)
cctm migrate --dry-run             # план без изменений
cctm migrate --path /path/to/proj  # мигрировать чужой проект, не заходя в него
```
